# 创作者投放业务数据

## 原始观察层

来源事件有来源编号、事件编号、修订、外部实体、发生时间和观察时间；同一来源同一
事件的更高修订替代先前修订。主体映射只在来源与外部标识的组合内有效，无法映射的
事件在现有摘要中列为未归属。通用金额是原始事件上的可选数值，不代表利润、节约额
或结算结果。

报告发布接口保留报告正文和摘要哈希，相同编号不接受不同内容。业务口径、结论的
适用范围和后续变化的影响需要与原始观察区分。

## 事件载荷约定

- 曝光 `exposure` / 点击 `click`：`campaign`（活动编号）、`creator`（创作者）；
  事件的 `entity` 经别名映射为顾客。
- 订单 `order`：`campaign`、`order_id`、`amount`（非负金额）。
- 退款 `refund`：`order_id`、`amount`；支持部分退款与多次退款，找不到对应订单的
  退款进入问题清单，不参与任何归因。

## 归因与结算口径

每笔订单在任何时刻最多只有一个结算对象。活动合同（`domain.py`）登记活动预算与
点击、曝光回看窗口；窗口内、订单之前的同顾客触达构成可解释路径：有点击取最后
一次点击，否则取最后一次曝光。规则无法确定性打破的多创作者触达（如同一时刻
并列）、胜出创作者未参加活动、活动未登记或重复订单进入待核，人工裁决前不结算、
不占预算；窗口内无合格触达为未归因，永不结算。

人工裁决独立于自动规则留痕并优先适用；归属纠正通过再裁决完成，每次裁决均可
回查。归因结论由不可变事件完整重放得出，结论变化时旧版本进入归因历史。

结算单按期间哈希封存，封存水位前已观测的事件与已作出的裁决才进入该期间，封存
内容（含每笔订单的触达路径、退款事件、净额与应付快照）不可变。封存之后的退款、
事件修订与归属纠正不回改旧单，而在新期间生成带正负方向的调整行；待核订单裁决
后在其后的期间结算。`order_trace` 串联一笔订单的当前结论、归因历史、裁决历史与
跨期间结算链，使市场与财务就同一笔变化在不同期间的结果看到一致解释。
